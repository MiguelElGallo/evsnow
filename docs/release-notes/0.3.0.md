# EvSnow 0.3.0 release notes

EvSnow 0.3.0 adds optional Snowflake Elastic Channels for streaming Azure Event
Hubs into Snowflake. Existing configurations continue to use Named Channels.

## Changes

- Add an Elastic adapter that obtains one implicit channel and waits for
  Snowflake to acknowledge each source batch before allowing a checkpoint.
- Preserve the original acknowledgement Future after a wait timeout. A retry of
  that same source batch observes the pending append instead of submitting it
  again. In-memory receipts also avoid resubmitting an acknowledged partition
  when another partition or a checkpoint write fails.
- Bound acknowledgement and shutdown waits. An unresolved acknowledgement or
  close error raises an incomplete-shutdown error; unacknowledged source batches
  remain uncheckpointed for replay.
- Preserve the full event envelope, including namespace, hub, partition, offset,
  sequence number, event body, and producer event identity.
- Require `snowpipe-streaming>=1.8.0`; the dependency lock selects SDK 1.8.1.
- Add configuration validation, a generated JSON schema, a usage guide, and a
  reproducible Azure and Snowflake test harness.

## Configuration

Three settings belong to the Snowflake connection. Environment variables
override the equivalent settings in a complete `[snowflake_connection]` TOML
table.

| Setting | Environment variable | Default |
| --- | --- | --- |
| `channel_mode` | `SNOWFLAKE_CHANNEL_MODE` | `named` |
| `ack_timeout_seconds` | `SNOWFLAKE_ACK_TIMEOUT_SECONDS` | `60` seconds |
| `close_timeout_seconds` | `SNOWFLAKE_CLOSE_TIMEOUT_SECONDS` | `60` seconds |

Set `SNOWFLAKE_CHANNEL_MODE=elastic` to enable Elastic Channels. Both timeout
settings must be positive integers. The existing pipe and key-pair credentials
are still required. Follow [Enable Elastic Channels](../how-to/use-elastic-channels.md)
for the complete setup and verification steps.

## Delivery behavior

Elastic mode provides at-least-once delivery. An acknowledgement confirms
durable buffering in Snowflake; it does not confirm table visibility or a
successful pipe transformation. Query the destination and the error table to
verify those outcomes.

Elastic Channels have no source offset recovery API and do not guarantee
ordering or exactly-once delivery. Append tokens identify requests for
acknowledgement handling; they do not remove duplicates. A process restart or a
failed append can cause source replay and duplicate rows. Use stable event IDs
when downstream deduplication is required. See
[Elastic acknowledgements and replay](../explanation/elastic-channels.md).

## Upgrade and validation

From the repository root, refresh dependencies and confirm the runtime version:

```bash
uv sync --locked
uv run evsnow version
```

The CLI reports `EvSnow v0.3.0`. Named Channels remain the default; enable
Elastic mode explicitly when you are ready to use its delivery behavior.

The regression suite passes 501 tests, including 35 focused Elastic tests
covering acknowledgements, timeouts, asynchronous failures, retained Futures,
partial partition failures, checkpoint write failures, shutdown, restart replay,
configuration precedence, and the generated schema. The broader suite also
covers Named Channels, consumers, orchestration, and the CLI.

Live validation on Azure Event Hubs Basic and Snowflake delivered all 200,000
expected events, with 200,000 distinct event IDs and zero missing events,
incorrect payloads, incorrect source metadata, or processing errors. The
consumer restarted between two halves and resumed from persisted checkpoints
at sequence number 50,000 on both partitions.

Replaying 40 source events produced 200,040 raw rows, 200,000 distinct event IDs,
and 40 duplicate rows, with zero processing errors. This demonstrates the
documented at-least-once behavior. Full measurements and cleanup read-backs are
recorded in [Elastic Channels live test](../development/live-test-results.md).

The temporary Azure resource group was deleted and its absence verified. The
isolated Snowflake warehouse is suspended and the test service user is disabled.
The result table and an event-ID view are retained for review; the view returns
200,000 events after removing the 40 replay duplicates.
